1 · Tags: classify on raw values, show labels

The most consequential cluster. Pylon stores option values (slugs) on tickets; its UI shows labels. The new label sync renames what every page displays — and several classifiers were keyed on the display wording, so the first sync would silently move tickets out of their buckets. Verified against real data: 64 alert tickets and 25 email-domain tickets would have dropped from the Product Report's clusters.

Report classification now keys on raw slugs fixed

report.py — _load, _is_reauth/_is_toggle/_is_access, _group_of callers, snapshot, chat context

_load now carries both views of every tag: category_raw/functionality_raw (the stable stored values) and the label-translated fields. All clusters, demand groups, FAQ predicates, console_ops, the compare snapshot and the chat rollup classify on raw; charts, CSVs and chat text keep showing labels.

Why: a label is wording a Pylon admin can change any day. Logic written against wording fails silently on the next rename — the report would have shown a fabricated month-over-month "decline" in alert relays after the first sync. A regression pin in t_report now installs a label map mid-test and asserts the clusters don't move while the categories chart re-words.

One catalog write path, atomic sync, honest field mapping fixed

funcheck.py (rewritten label/catalog layer) · app.py catalog endpoints · vault.py set_raw_settings

The label map is memoized with an explicit invalidate_labels(); cleaning rules live once in clean_entries; the Admin editor and the Pylon sync both go through save_catalog/clear_catalog (which also audit); the sync resolves field slugs through the same Admin mapping the checker reads, falls back to the slug when Pylon returns a blank label, and persists all four settings in one transaction via the new vault.set_raw_settings. Reset clears a kind's list and its slice of the label map together.

Why: two cleaning definitions meant a synced entry could fail to round-trip through the Admin textarea; a torn multi-setting write would translate tags into a vocabulary the catalog no longer contains — which reads as data corruption, not a crash; and a sync that ignores the field mapping splits from the checker the day a field is repointed.

Custom-field fetch now paginates fixed

pylon.py — fetch_custom_fields

Follows pagination.cursor with per-page retry instead of reading only the first page.

Why: the catalog sync and the Slack field-drift warning are now built on this call. Page one alone would sync a partial vocabulary and report healthy fields as "removed from Pylon".

Weekly page uses the same translator as everything else fixed

weekly.py — _canon_category

Category display goes through funcheck.canon, with the old _humanize guess only as the fallback for unmapped values.

Why: two competing translators meant the weekly and monthly pages could name the same category differently — "General Question" on one screen, "General FAQ - How to questions" on the other.

2 · Concurrency and the scheduler

The deep platform audit found the locking story had three related holes; together they allowed two full QC runs of the same date at once — double Vertex billing and interleaved grade writes.

Scheduler and manual runs now contend for the same locks fixed

scheduler.py — run_pipeline

The pipeline now holds fetch:{date} and qc:{date} — the very names the manual endpoints hold — alongside its own daily_run lock.

Why: the locks guarded disjoint names, so an operator pressing Run QC at 09:31 scored the same date the scheduler started at 09:30. The collision the lock table exists to prevent was unguarded.

Stale-run timeout no longer shorter than the lock TTL fixed

db.py — STALE_RUN_MINUTES 15 → 45

Why: the code's own comment states the invariant ("must exceed the advisory lock TTL") and shipped with it inverted: a slow 20-minute run was declared dead at minute 15, retried into LockBusy, then duplicated alive at minute 30 when the TTL lapsed.

Locks release only their own acquisition fixed

db.py — advisory_lock

The release deletes WHERE name AND holder AND acquired_at match, not by name alone.

Why: if run A outlived its TTL and run B took the lock, A's cleanup deleted B's lock — letting a third caller in while B still ran.

“Run now” satisfies the day's schedule fixed

app.py run_now · scheduler.py _already_ran

A dateless Run now records today's trigger date; the schedule guard counts any successful run of the same target, not only triggered_by='scheduler' — and now also matches run_date, so a backfill of another date can't mask today's run.

Why: a successful manual run at 09:00 was invisible to the 09:30 tick, which fetched, scored and posted the identical Slack report a second time.

Ephemeral master key generated once, not per call fixed

vault.py — _load_master_key

Why: on a read-only filesystem without QC_MASTER_KEY, every call minted a fresh key — the OAuth state was signed under key #1 and verified under key #2, so sign-in looped on "Sign-in expired" forever. The warning promised sessions wouldn't survive a restart; they didn't survive a request.

3 · Security and permissions

Evidence CSV neutralises spreadsheet formulas fixed

app.py — report_evidence_csv

Why: ticket titles and resolution text are customer-controlled; a title starting =, +, - or @ executes when the exported CSV opens in Excel or Sheets. The sibling day-export already escaped exactly this — the report export didn't.

GET /api/weekly no longer writes as a side effect of viewing fixed

app.py — get_weekly + _csat_refresh_due

The CSAT sweep (Pylon crawl + ticket writes) runs only for operators/admins, throttled to one sweep per period per 10 minutes.

Why: members are documented as read-only, yet any member merely opening the weekly page triggered paginated Pylon API calls and unaudited UPDATE tickets writes — on every reload.

4 · Scoring pipeline consistency

The scoring audit's theme: scorer, evidence and the persisted advice notes are three statements of the same rules, and several had drifted from the configuration that Admin/Rules can edit.

R8 advice follows the configured conditions fixed

qc_runner.py — _r_check_notes

The failure note only names conditions in rules.r8_conditions(), reads values the way the scorer does (interpreted_value first), and only suggests a Jira link when that condition is still required.

Why: after an admin dropped conditions, the morning Slack report told agents to fix fields the scorer no longer checks — while never mentioning the one thing actually missing.

Legal-handoff advice names the configured tag fixed

qc_runner.py — _r_check_notes (R5)

Why: the note hardcoded "@legal-ops" while the scorer passes on whatever tags the status policy lists — edit the matrix to "@legal" and the advice sends people to type a tag that no longer counts.

Evidence reads the oncall link through the field map fixed

evidence.py — _Context

Why: the one remaining hardcoded slug. Remap the field in Rules and scoring passes R5 via the Slack thread while the evidence panel sees no link and asserts the handoff never happened.

One corrupt ticket no longer sinks its whole batch fixed

qc_runner.py — _build_ticket_block

A malformed stored custom_fields document degrades to "fields unreadable" instead of raising while the batch prompt is assembled.

Why: the exception fired before the per-ticket retry could catch anything, so five healthy batch-mates were marked skipped for one bad row — defeating the fallback the function promises.

Run stability measured over what the run actually graded fixed

qc_runner.py — _snapshot_and_compare

The snapshot applies the excluded-state filter and masks r_fails to enabled checks.

Why: frozen archived grades padded the "unchanged" count (a day with 10 of 20 graded tickets flipping still read 90% stable), and a disabled check's Fail was recorded beside a Pass overall in run history.

Header stats share the day panel's scope fixed

db.py — ticket_stats

Why: the one grade surface without the excluded-status filter: with archived excluded, the pills said "67 tickets, 23 unreviewed" over a panel showing 44 — the exact split the shared-clause refactor existed to end.

Slack field-drift warning can't suppress itself fixed

slack.py — _field_drift_blocks

The "already reported" signature is stored only after the warning is actually built, and cleared on recovery so the same drift re-alarms if it returns.

Docstring pointed at the wrong credential home fixed

scorer.py — _fetch_slack_thread

Why: it said "SLACK_USER_TOKEN in the environment"; the code reads the vault. An operator following the doc gets silently empty Slack threads — and R5 failures — on every oncall ticket.

Refetch merges CSAT instead of clobbering it fixed

weekly.py — csat_json_for_store

Why: the two writers of tickets.csat_responses disagreed: the weekly page carefully merged survey responses (with comments), then a plain day refetch replaced the column with the thinner issue-level list — silently losing the comments.

Drive calls off the event loop fixed

share.py — meta, send

Why: drive_status and the sheet upload are synchronous httpx calls with 20–120 s timeouts, called directly from async endpoints — while Google answered, every other request in the app stalled.

6 · Reviewed, deliberately not changed

Real findings where the fix is a bigger decision than a review should make unilaterally. Each is worth a ticket.

  • evidence.py R5 explains by hardcoded state names while the scorer follows the editable status policy. Edit the policy matrix and the evidence panel can contradict the stored verdict. Fixing it properly means rebuilding evidence's R5 on status_policy — a refactor with its own test surface, not a patch.
  • qc_fingerprint hashes R8/R9, which the prompt never contains — a Jira link appearing re-bills an identical prompt. But changing the fingerprint definition invalidates every stored fingerprint and re-bills the whole archive once; the cure costs more than the disease until batched with another prompt change.
  • _compute_overall checks a3 for "Needs Review", a grade a3's enum can never produce — so a3's "Needs Improvement" uniquely never demotes a ticket. Whether it should demote is a grading-policy decision, not a code fix.
  • NULL-state tickets vanish under state NOT IN (…) (SQL three-valued logic). This is pinned in tests as current app-wide behaviour; flipping it changes historical counts everywhere at once, so it stays a documented convention (see CLAUDE.md) until decided deliberately.
  • Sync overwrites hand-curated catalog lists — by design: the button's contract is "Pylon is the source of truth", and the Admin editor remains for local curation between syncs.
  • Stored funcheck verdicts keep pre-sync spellings until a re-run — a transitional inconsistency the fingerprint system resolves on the next monthly check, not worth forcing a paid re-run.
  • fetch_and_store reads each ticket's prior CSAT row-by-row (an N+1 from the CSAT merge). Correct, and a day's fetch is ~100 rows; noted for whoever next touches the fetch loop.
  • qc_runner's coaching text shows a raw slug in one message — cosmetic; the advice remains actionable.
  • Analytics fail-ticket links were flagged as an XSS sink but verified safe: the server nulls any non-http(s) link before the client sees it.

7 · Standards for a multi-contributor repo

The review's recurring pattern isn't sloppiness — it's several careful people holding different mental models: two CSAT writers with opposite merge semantics, two category translators, two pass-rate colour scales, three statements of R5, two lock-name schemes. The repo had no written conventions to converge on.

CLAUDE.md added at the repo root fixed

A one-page contributor guide pinning the rules whose violations shipped the bugs above: run ./tests/run.sh; classify on raw slugs, display labels; one shared predicate for excluded statuses; the advisory-lock naming contract and the TTL invariant; NULL NOT IN; settings through the vault registry with audit rows; escape-and-token discipline on the frontend; and a commit-message convention (history currently mixes Feat:, Enhanc:, feat: and bare sentences).
